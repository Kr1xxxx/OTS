# Local Feishu notification configuration

Order notifications read `~/Library/Application Support/TradeOrderSystem/feishu-settings.json`. This file is local deployment data; it must never be bundled, committed or uploaded. Application replacement preserves it because it is outside the app bundle. Bot credentials continue to live in the existing lark-cli profile, not this file.

The JSON object contains three strings: `profile` (the existing CLI profile name), `chatName` (the group display label), and `chatId` (the group's oc_ identifier), plus an optional `cliPath` (the full path of lark-cli when it is not found automatically). Fill it in from **设置 → 飞书通知**: the page validates the values with the same rules as the reader, writes the file atomically with owner-only permissions (0600) and the change takes effect without a restart. Saved `profile` and `chatId` values are never sent back to the page; leaving those fields blank keeps them. The file can still be written by hand; it is read again on every send, a UTF-8 BOM is accepted, and the settings page shows why a hand-edited file is rejected (bad JSON, curly quotes, placeholder values, wrong chat id format, symbolic link, too large). Missing or malformed settings disable notifications with a clear error while order storage remains available, and the 「保存后发送到飞书群」 switch defaults to off. Notifications always run with an explicit profile and `--as bot`.

lark-cli is looked up in `TRADE_LARK_CLI` (tests), the saved `cliPath`, `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.volta/bin`, `~/.npm-global/bin`, `~/.bun/bin`, `~/bin` and every nvm Node version. The npm JavaScript wrapper runs with the app's Node; a native program (`make install`, Volta shim) runs directly. lark-cli receives only an allow-list of environment variables (no `TRADE_*` token, port or data directory). Errors are read from stderr, as lark-cli writes them, and mapped to a Chinese reason (missing permission, bot not in the group, expired credentials, unknown profile, rate limit, offline); raw CLI output is never shown or stored. A timeout ends the whole process group so a wrapper's native child cannot send later, and is recorded as "may already have been sent"; resending after it asks for confirmation first.

New releases declare `OTSFeishuSettingsVersion = 1` in Info.plist and bundle `feishu-settings.js`. The updater refuses a release without this support when a local settings file exists, before quitting or replacing the current application. Compatible releases keep normal updates; a user without local Feishu configuration does not gain this update restriction. This gate prevents older public packages from silently reconnecting to placeholder settings; future release builds must retain the reader and metadata. The optional `cliPath` key is ignored by older readers, so the version stays 1.

Automated notification tests use a fake CLI and synthetic group/profile data. They cover app replacement with the same independent settings directory, missing configuration, the settings page, exact bot identity, image messages (including skipped AVIF and over-10 MB images), Markdown neutralisation, error reasons from stderr, the environment allow-list, native CLIs, process-group timeouts, idempotency and controlled retry. They do not send real group messages.
